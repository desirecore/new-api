# New API v1.0.0-rc.45-desirecore.1 升级部署说明

本版本基于 QuantumNous/new-api 官方 v1.0.0-rc.45，保留 desirecore 的分组模型链路视图。Thinking round-trip 不在发布范围，旧 Alibaba PR 4810 延续 rc.43 候选的排除决定。发布镜像不自动部署生产。

## 1. 制品与版本

- 源码标签：`v1.0.0-rc.45-desirecore.1`，发布后不移动。
- 产品主线：`desirecore/main`；候选：`release/v1.0.0-rc.45-desirecore.1`。
- 腾讯云：`ccr.ccs.tencentyun.com/desirecore/new-api:v1.0.0-rc.45-desirecore.1`。
- GHCR：`ghcr.io/desirecore/new-api:v1.0.0-rc.45-desirecore.1`。
- 架构：linux/amd64、linux/arm64；单架构标签分别追加 `-amd64`、`-arm64`。
- 应用 VERSION 为完整发布版本号；OCI revision 指向实际源码提交。
- 最终构建结果、镜像 digest、CI 链接以本版本 GitHub Release 附件 `release-metadata.json` 为准。生产固定 digest，避免重复拉取时版本漂移。

```sh
gh release download v1.0.0-rc.45-desirecore.1 \
  --repo desirecore/new-api --pattern release-metadata.json
NEW_IMAGE=$(jq -er '.images.tencent.index' release-metadata.json)
```

## 2. 升级前必须满足的业务条件

线上 rc.33 可直接升级，无须先部署 rc.43。继续使用现有 MySQL 主库和日志数据，不迁移到 PostgreSQL，不用新装包覆盖现有数据库。

server 必须已经部署支持 scoped 契约的版本，并准备：`NEWAPI_AUTH_CONTRACT=scoped`、服务账号 ID、新管理员 PAT 和该账号自己的 `NEWAPI_ADMIN_VERIFICATION_PASSWORD`。这些秘密通过既有密钥系统交付，不写进仓库、工单或 shell 历史。生产服务账号 2 的已核对角色是 10、MFA 未启用；仍须按实际验证方法处理，不关闭管理员 MFA 或绕过 proof。先在隔离环境验证 server 的开户、模型 Key 管理、额度变更、分组、账号合并/停权及日志同步，再安排切换。只读或常规操作兼容不代表旧密码重置流程兼容。

所有仍被业务后台使用的旧管理 PAT 都纳入迁移，包含管理员及普通用户 PAT；模型调用 API Key（sk-…）不因本次管理 PAT 变化而批量重建。首次新版本启动会持久化 30 天旧 PAT 过渡期限，重启不会重置。上线前备好存量迁移清单、失败重试及人工对账方案；不要等过渡期届满才处理。新 PAT 明文只在创建时返回，迁移必须遵守登录和一次性验证流程，不可从新表反查明文。

网关需通过 Kubernetes Secret 固定 `SESSION_SECRET`、`CRYPTO_SECRET`。此前线上未设置这两个值；首次设置会影响既有会话及临时签名链接，应纳入维护窗口，并在后续版本保持稳定。它们与 server 自身保存 New API PAT 的加密密钥是不同配置，不可顺带更换 server 的加密密钥。

## 3. 备份和窗口

暂停开户、账号合并及新视频任务提交，排空流式连接和在途任务。当前是单副本部署，不承诺无中断切换；升级期间不要让旧版与新版同时承担敏感管理操作。

准备当天最新的一致性 MySQL 备份，覆盖主数据和实际日志库，并验证压缩完整性及恢复。备份 Deployment/Secret 的既有受控版本、server 协议/凭据状态，记录升级前镜像 digest、关键表行数、定价/分组配置、账务同步游标与未完成任务数。秘密备份权限应为仅运维可读；以下 Deployment 文件本身也按私有资料处理。

```sh
umask 077
kubectl -n prod-newapi get deployment new-api -o yaml > new-api-before.yaml
kubectl -n prod-newapi get deployment new-api \
  -o jsonpath='{range .spec.template.spec.containers[*]}{.name}{" "}{.image}{"\n"}{end}'
```

备份应使用实际数据库名称和既有安全连接方式；不要在命令行粘贴生产数据库密码。本版本既有演练使用 2026-10-11 历史生产备份，不能替代部署当天备份。

## 4. k3s 切换

以下仅为部署操作说明，构建流程不执行这些命令。使用标准 kubectl 或主机上的 sudo k3s kubectl。先确认实际容器名（此前 Deployment 为 new-api），沿用现有镜像拉取凭据、数据库 Secret、数据目录及服务端口。

为避免单副本滚动策略启动两代服务，在维护窗口使用 Recreate；升级失败或窗口结束后可按原备份恢复策略。务必先排空连接，因为 Recreate 会造成短暂不可用。

```sh
# 在受控环境中读取本次制品元数据。
NEW_IMAGE=$(jq -er '.images.tencent.index' release-metadata.json)
kubectl -n prod-newapi patch deployment new-api --type=merge \
  -p '{"spec":{"strategy":{"type":"Recreate","rollingUpdate":null}}}'
kubectl -n prod-newapi set image deployment/new-api new-api="$NEW_IMAGE"
kubectl -n prod-newapi rollout status deployment/new-api --timeout=600s
kubectl -n prod-newapi get pods -o wide
```

切换前后同步安排 server 的 scoped 配置及服务凭据，暂停期间完成验证；如验证失败，保持相关写操作暂停。不要把旧 PAT 过渡期误当作旧敏感操作接口的兼容期。

## 5. 上线验收

检查 /api/status 版本、数据库迁移日志、Pod 重启次数及健康探针；保留两次启动结果，确认迁移幂等。确认服务账号与普通用户分别能执行其允许的操作，密码重置/停权携带正确 proof，存量模型 Key 可用。

至少完成：已有用户一次普通模型请求和流式请求、一个真实启用的图片/视频模型任务（可能产生费用，按部署验收安排）、分组/路由优先级/重定向及链路视图、额度变更与实际扣费、消费日志查询和 server 同步/去重。记录请求、扣费和日志三者一致；新版本构建及静态测试不替代真实供应商验收。

核对原有模型定价、分组倍率、用户/Token/渠道/路由能力/历史任务及日志数量。确认 LegacyAccessTokenRetireAt 的真实值，安排到期前完成存量 PAT 迁移。若旧 Alibaba 补丁模型被重新启用，必须单独验证其提交支持；历史任务可读不等于旧模型可重新提交。

## 6. 回退

保留升级前的完整 rc.33 镜像 digest；以前核对的生产镜像为 `ccr.ccs.tencentyun.com/desirecore/new-api@sha256:d0436db6f653e88c88d74d1dbe5b0569565751ed1899bf54f1d49caca60ce849`，操作时以当天记录为准。回退前暂停上述写入并排空请求。

在独立生产历史副本上已验证 rc.45 两次启动后回切 rc.33，原数据保持可读；这不涵盖所有 rc.45 新写入语义。新 scoped PAT 不能用于 rc.33，因此需要同步恢复 server 的 legacy 协议和对应旧凭据。保留凭据迁移前的受控备份及映射，避免仅回退镜像后后台继续持有新 PAT。

```sh
# OLD_IMAGE 必须取自维护窗口前保存的实际 digest。
kubectl -n prod-newapi set image deployment/new-api new-api="$OLD_IMAGE"
kubectl -n prod-newapi rollout status deployment/new-api --timeout=600s
```

镜像回退不自动回退 server，也不自动恢复数据库。若升级后产生用户、额度、任务或账本写入，先对账再决定恢复策略；不要直接用整库旧备份覆盖而丢失新增账务。已有 LegacyAccessTokenRetireAt 不因回退后再升级而重置。

## 7. 验证边界

rc.45 候选曾通过全量前端 2392 项测试、后端相关测试和真实 SQLite/MySQL/PostgreSQL 测试。历史生产副本演练保留六张核心表原有列指纹、46 项配置、两次启动一致性和回切 rc.33；12 个历史视频任务在两版均可读。server 正式 scoped 客户端也在账号 2 角色的隔离副本上完成认证链路测试。使用过的数据库版本为 SQLite 3.50.4、MySQL 8.0.46、PostgreSQL 16.15；此前核对线上 MySQL 为 8.0.35。

本次发布的最新 CI 结果见 Release 元数据链接。上述历史结果不代表当天生产快照、实际业务库编排、所有真实模型或所有最低数据库版本已完成验收。构建和发布制品不会改变生产状态。
