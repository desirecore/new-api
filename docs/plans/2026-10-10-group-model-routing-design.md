# 分组模型链路视图设计

日期：2026-10-10
状态：用户已确认书面设计；进入实施计划评审，尚未实施
关联需求：`2026-10-10-gateway-customization.md`

## 1. 用户目标

以分组为入口回答：

1. 这个分组配置了哪些模型，哪些模型没有启用的渠道？
2. 每个模型连接哪些渠道，渠道优先级与权重如何？
3. 每个渠道上的模型重定向经过哪些名称，最终发送什么模型名称？
4. 为什么某条配置链路不能参与普通选择？
5. 在给定时间内，这个分组的模型实际产生了多少访问和用量？

页面不引入“对外模型”等新管理概念，不要求模型库先登记，不建立新的路由配置真相源。

## 2. 方案选择

### 推荐：独立只读聚合模块

新增分组链路查询接口和独立前端 feature。只读现有配置，形成用于展示的 DTO，保留现有管理页、转发与计费行为。对已有文件的接入预计只涉及路由注册、页面入口和翻译。

优点：字段投影可排除密钥；可以完整纳入禁用配置与空分组；前后端不各自重建关联关系；变更集中，便于同步上游。

替代一：纯前端拼接现有分组、渠道、模型库接口。改动少，但需要分页拉全渠道、获取过量配置并在前端推导路由；现有模型关联返回的渠道只有名称和类型，缺少完整链路字段。不推荐作为正式方案。

替代二：改造路由核心为完整 explain/trace 引擎。能解释真实请求的全部决策，但触及请求生命周期，增加上游合并和回归成本。留待后续单次请求追踪需求，不作为首版前提。

“低侵入”的准确含义：不改现有请求行为和持久化结构；仍需新增代码与少量入口接入，并跟踪上游路由语义变化，不能承诺零冲突。

## 3. 页面结构

推荐在模型管理中增加“分组链路”入口，内容实现放在独立 feature。保留原有模型库、厂商、部署与渠道管理入口。

主界面是一张交互式关系图。菜单只负责页面入口，分组选择器负责切换分组；不通过多级菜单逐层查看渠道。桌面布局：

```text
分组 [premium ▼]   搜索模型/渠道   状态筛选   刷新
模型数 / 启用渠道数 / 配置异常数             配置读取时间
[模型链路树 | 共享渠道网络 | 表格]
┌────────────────── 交互画布 ─────────────────────────┐
│                ┌ model-a → 优先级层 → 渠道 → 映射链  │
│ premium ───────┼ model-b → 优先级层 → 渠道 → 映射链  │
│                └ model-c（待展开）                   │
│                                      缩略图         │
│ [+] [-] [适应窗口] [定位选中] [全部折叠]              │
└────────────────────────────────────────────────────┘
点击节点 → 右侧详情抽屉（关闭后保留画布视角）
```

选择分组后直接显示该分组节点及当前页的模型节点，默认折叠渠道；点击模型展开链路，支持多个模型同时展开。初次进入不会展开所有模型的全部渠道。没有模型时显示空状态；只有一个模型时自动展开。

分组、聚焦模型、视图模式、搜索和筛选同步到 URL 查询参数，支持刷新与分享。模型名作为 query 值编码，避免名称包含 `/` 时破坏路径。缩放、平移与临时展开集合留在当前页面状态；每个分组/模式分别保留本次访问中的视角。打开/关闭抽屉或刷新不自动重置视角；切组或首次载入时适应窗口。

### 分组选择

- 分组名、配置模型数、启用渠道数、异常提示。
- 没有渠道的已配置分组仍显示“未配置模型”。
- 渠道引用了未登记于分组倍率配置的名称时仍显示，标记“分组配置不完整”，不静默丢弃或自动修复。
- 搜索分组，不引入本产品套餐命名或新增业务分组体系。

### 模型节点与辅助表格

- 模型名称、启用/配置渠道数、优先级层数、重定向与配置异常提示。
- 状态用“存在启用渠道”“仅禁用渠道”“配置不一致”等事实用语；启用不代表上游在线或当前请求必定可用。
- 首版默认同时包含启用和禁用配置，支持筛选。
- 模型库的隐藏状态只作展示信息，不能误判为网关禁止调用。
- 默认使用图形，表格作为辅助模式提供等价信息、筛选和详情入口，不能成为查看链路的必经步骤。

### 两种图形模式

**模型链路树（默认）**：按“分组 → 模型 → 优先级层 → 渠道 → 映射”从左到右分层。每条模型链路独立；同一渠道服务不同模型时可以出现多个卡片，均显示真实渠道 ID。适合回答某个模型具体如何配置。

**共享渠道网络**：相同渠道合并成一个节点，按“分组 → 模型 → 共享渠道”保持分层布局。模型到渠道的关联线上显示该模型的优先级、权重和映射摘要。节点显示渠道的共用状态；映射详情跟随选中的模型—渠道关联展示，不能把不同模型的映射链无条件接到共享渠道后面，产生虚假的路径组合。

共享渠道网络中的优先级属于模型—渠道关系，不能把一个渠道全局标成“首选”或“后备”。点击共享渠道高亮当前已加载的全部关联模型，并提供按该渠道筛选完整分组模型清单的入口。未加载部分明确计数，不声称当前子图覆盖全分组。

两种模式使用相同后端事实数据，由前端图构建器投影成不同节点/边结构，不维护两份业务配置。模式切换保留选中的业务对象；某对象在新模式中有多个图节点时定位其对应模型的那条链路。

### 交互约定

- 展开/折叠按钮与节点选中操作分离：展开按钮控制子图，点击节点正文选中并打开详情。收起模型时清理其隐藏图节点选择，焦点回到模型节点。
- 拖动空白画布平移；支持滚轮/触控板缩放、缩放按钮、适应窗口、定位选中与缩略图导航。节点默认不可拖动，不可连接、删除或编辑；画布平移不改变配置。
- 搜索作用于当前分组全部模型/渠道，不仅搜索已加载节点。搜索结果可定位模型或筛选渠道关联模型；定位时加载必要详情，再高亮路径。
- 悬停显示摘要，点击后在抽屉查看完整字段；触屏和键盘不依赖悬停即可获得同等信息。
- 选中模型、渠道或关联边时高亮相关路径，其他路径淡化。点击空白取消高亮；关闭抽屉后还原原节点焦点。
- 筛选启用/禁用、存在映射、存在诊断；筛选不会把已禁用渠道标成可选。搜索和筛选结果显示命中数与全组总数。
- 配置连线宽度一致。高优先级用分层与文字标识，禁用用虚线及状态文字；颜色只作辅助。禁用流动动画，避免暗示正在转发请求。
- 优先级层内按渠道 ID 稳定排列；共享渠道模式按稳定 ID 排列。刷新无结构变化时保留位置，有结构变化时只调整受影响子图。显式“适应窗口”才重新框选全部可见图。

### 图规模与渐进加载

模型首屏 50 个，接口分页上限 100，提供“加载更多”；显示“已加载 N / 共 M 个”，不静默截断。每个模型展开时按需读取详情并缓存，独立加载/失败状态不会清空其余子图。

提供“展开当前已加载模型”；展开只作用于已加载集合，最多 4 个详情请求并发。画布初始可见节点预算 300 个，超出时保留模型摘要与明确的继续加载入口；单模型超过预算时分批展示渠道，并显示已展示/总数，不能偷偷丢弃后备层或禁用渠道。预算为 UI 渲染策略，不改变接口的完整配置事实。

布局仅处理已展示子图。树模式按子树高度分配位置；网络模式按层与稳定顺序排列，并在布局函数中处理节点碰撞。先不引入力导向动画或新的自动布局依赖；若后续实际数据证明交叉线不可读，再单独评估布局引擎。

移动端保留分组选择、搜索、图形和详情入口，提供全屏画布与同等信息的纵向列表切换；长名称、键盘导航和屏幕阅读器通过辅助表格/列表获得完整内容。

### 单模型配置链路

```text
premium → model-a
          ├─ 优先级 100：普通选择的首选层
          │    ├─ 渠道 A，权重 80 → model-a → vendor-model-a
          │    └─ 渠道 B，权重 20 → model-a（无重定向）
          ├─ 优先级 50：后续重试可能使用
          │    └─ 渠道 C，权重 10 → model-a → alias → vendor-model-b
          └─ 不参与当前普通选择
               └─ 渠道 D：已禁用
```

同优先级的渠道并列，不按权重画成依次尝试的串行路径。优先级由高到低排列；同层按渠道 ID 稳定排列，权重另行显示。后备层使用不同视觉样式，连线表达候选层级，不保证一定发生重试。

渠道卡片显示 ID、名称、渠道类型、状态、优先级、原始权重、配置映射链及诊断。名称相同的渠道通过 ID 区分；映射目标不是新渠道节点，也不自动成为分组模型列表中的模型。

支持展开长映射链；循环、非法映射、过长链均显示明确诊断。自身映射按现有运行时语义处理，不把所有 `A → A` 误报为循环。无映射显示原模型名称。

首版只读；不提供拖拽改权重、直接编辑连线或自动修复。图上“拖动”指移动视角，不指改变路由。跳转已有渠道管理页须沿用现有授权，不因图中出现渠道而扩大编辑权限。

## 4. 数据来源与口径

### 分组

取现有分组配置、渠道分组引用和 abilities 分组引用的并集，返回来源标识。仅使用现有 `GET /api/group/` 会漏掉未登记倍率的渠道分组，因此不能把它作为唯一发现来源。

首版主视图展示具体分组。`auto` 是请求时的分组选择策略，受用户可用分组、Token 设置及顺序影响，不能当作拥有固定模型集合的普通分组；遇到此名称显示专门说明，不绘制一个全局固定的 auto 链路。面向具体用户/Token 的展开留待后续。

### 模型与渠道

以 channels 的分组和模型配置建立完整配置拓扑，补充 abilities 核对。正常关系为一条渠道对每个“分组 × 模型”提供能力记录。

- channels 保留禁用、尚无流量的配置。
- abilities 用于发现配置与能力表的不一致，不自动回写。
- 模型元数据只做可选补充，不通过公开 pricing 目录筛选模型。
- 不扩展列举所有可能的模型别名；首版展示明确配置的模型名。
- 数据读取时间只代表配置观测时间，不代表所有渠道状态、设置和 abilities 处于跨来源的原子快照。

### 配置与运行时的区别

接口明确返回 `basis=config`。存在内存路由缓存时，当前实例的缓存可能尚未同步配置；首版不声称正在查看各实例的实时缓存，也不调用缓存重建来“刷新”。多实例不做未经证实的全局一致声明。

数据库与缓存路径对原始分组值和模型匹配的处理可能不同。展示适配层不得静默修剪后宣称实际可路由；遇到异常空白、缺失能力记录等显示诊断并保留原配置事实。

### 优先级与权重

高优先级先参与普通选择，同层按运行模式的权重规则选择。重试是否发生、是否进入下一层由错误类型、重试预算与策略共同决定；层耗尽后的行为也不能简化为“每个渠道只试一次”。

首版显示优先级、原始权重和规则说明，不输出“预计全局命中率”。当前缓存路径和数据库路径的选择算法存在差异，未经对应模式的契约验证，不输出数值选择概率。未来若提供比例，只能标明“给定候选集和优先级层的条件选择比例”，不能替代历史流量占比。

固定提示说明：指定渠道、会话亲和、请求端点过滤、模型匹配、插件约束、auto 分组和用户/Token 限制可能改变候选集或选择过程。首版不会完整解释这些请求上下文。

### 重定向

展示所选模型在每个渠道上的配置映射链，适配现有 `ModelMappedHelper` 的链式映射、修饰模型回退、自身映射和循环判断语义。适配层集中在新模块，不在前端再写一套推导。

不通过构造真实 relay 请求进行模拟，不消耗密钥或额度，不触发远程请求。渠道特有的适配器改写、插件别名或其他无法从所选字段可靠解析的部分标记为“仅展示渠道模型映射”；不能把配置映射终点宣称为所有协议下最终上游名称。

## 5. 访问指标分阶段加入

### 第一交付：配置拓扑

完成分组发现、模型链路树、共享渠道网络、辅助表格、优先级分层、权重、映射链、配置诊断与上述交互。无需任何历史流量或额外采集。

### 第二交付：已有用量数据

接入现有 `quota_data` 聚合能力，按实际 `use_group`、模型、渠道汇总请求计数、Token、消费 quota 和已记录请求占比。优先复用查询与格式化，不复用整个 dashboard 页面状态。

- 明确称为“已记录消费请求数/占比”；不能视为包含所有失败尝试的总访问量或成功率。
- 展示统计窗口、数据源与聚合延迟说明；导出未启用、查询失败、无记录分别表达，缺数据不能伪装为零访问。
- 历史有流量但配置已删除的模型/渠道放入“仅历史记录”，不把它们画成当前候选链路。历史映射无法从当前配置反推。
- 图中配置权重与历史占比并列，禁止以历史流量线宽表达配置优先级。
- 图中显示的 group 是实际使用的分组，不能推断为用户的套餐分组或 Token 原始选择。

现有 `/api/data/flow` 与 dashboard 桑基图已覆盖实际用量流向；可复用其图表能力和指标语义。正式接入时评估是否增加按 group/model 聚合的窄查询接口，避免拉取全站逐用户数据再由前端过滤。

### 后续独立设计：性能与真实请求追踪

成功率、首响应 P95、尝试级重试率、每次尝试耗时和完整决策原因需要单独核实日志完整性与计算口径。已有 `request_id`、`use_channel` 和 `frt` 能支撑部分诊断，但不能保证还原完整请求链路。此阶段可能增加采集点，不属于首版的只读、无请求路径改动承诺。

## 6. 只读接口草案

新增独立命名空间，以下路径是本功能的设计约定，不是现有 API：

| 接口 | 用途 |
| --- | --- |
| `GET /api/model-topology/groups` | 分组列表、来源与配置摘要 |
| `GET /api/model-topology/models?group=...&keyword=...&channel_keyword=...&channel_id=...&status=...&has_mapping=...&has_diagnostics=...&p=...&page_size=...` | 当前分组的模型分页列表与全组搜索/筛选 |
| `GET /api/model-topology/detail?group=...&model=...` | 单个分组模型的完整配置链路 |

使用项目标准响应信封。模型列表按模型名稳定排序，分页上限 100；筛选在计数和分页前执行。分组与模型参数精确匹配，搜索参数单独处理，不将 `*` 或 `%` 暗中视为路由通配规则。

模型项包含配置/启用渠道数、层数、映射/诊断摘要及渠道 ID 索引（不含认证信息），用于折叠节点和判断共享渠道关联总数。分页响应同时给出全组模型总数、筛选命中数和配置读取时间。复杂映射只在详情接口解析；列表诊断摘要仅覆盖该次列表查询已检查的项目，不承诺提前完成所有映射诊断。`has_diagnostics` 筛选仅按此明确范围工作。

图节点 ID 和边 ID 由前端基于稳定业务键构造：模型键为 `(group, model)`；树模式渠道键为 `(group, model, channel_id)`；共享模式渠道键为 `(group, channel_id)`；映射节点带所属模型、渠道及步骤索引。不得用显示名称单独作为渠道 ID，也不得用每次请求随机 ID 导致刷新重建全部节点。

不存在的分组/模型返回明确的 404；存在但无模型的分组返回空列表。配置映射损坏返回包含局部诊断的详情，不让一条渠道破坏整张图；主配置查询失败返回错误，不返回伪造空列表。

详情 DTO：

```text
group, model, observed_at, basis=config, runtime_mode
summary: configured_channels, enabled_channels, priority_layers
tiers[]:
  priority
  channels[]:
    channel_id, channel_name, channel_type, channel_status
    configured_weight, ability_consistency, related_model_count_in_group
    mapping: names[], status, scope=channel_mapping
    diagnostics[]: code, severity, affected_channel_id
excluded_channels[]
limitations[]
```

只返回展示所需的字段。不得序列化完整 Channel，或返回渠道密钥、认证头、自定义认证内容、私有地址、原始 setting/other_info 等。映射只返回当前模型的相关链，不返回整个映射表。

沿用既有管理接口的权限体系，并在实现时核对渠道和日志的细粒度权限；无渠道读取权限不得通过此接口获取渠道信息。首版不新增认证方式、不修改现有认证流程。指标权限独立校验，不因可看配置就自动可看敏感用量。

## 7. 模块与组件复用

后端推荐新增 `controller/model_topology.go`、`service/model_topology.go`、`model/model_topology.go`；分别负责参数/授权、展示聚合/诊断、限定字段查询。命名为实施建议，可按实际职责缩减；不为少量逻辑强行分层。

前端推荐 `web/src/features/model-topology/`，路由入口使用现有模型管理分区模式；数据请求使用项目 api 和 React Query。首版手动刷新，配置查询短期缓存；不为浏览页面新增后台轮询任务。

已检查的复用候选：

- `components/model-group-selector.tsx` 的分组选择能力、`group-badge.tsx`。
- `components/data-table/` 的列表、分页与静态表格，以及 EmptyState、LoadingState、ErrorState。
- `components/ai-elements/canvas.tsx`、`controls.tsx`、`node.tsx`：仓库已有 React Flow 画布、缩放控件和卡片节点封装。Canvas 的 props 最后透传，可覆盖默认编辑行为；本页必须显式禁止 Delete/Backspace 删除、连线和节点拖动，并启用画布拖动、关闭框选。实现时检查内置 Controls 的编辑切换控件，确保无法重新开启编辑；必要时为公共封装增加保持默认行为的兼容 props，而不是复制画布。
- `components/ai-elements/edge.tsx`：现有 Animated 边带流动圆点，不适合纯配置图；本页使用 React Flow 的静态边或组合 BaseEdge，保留路径高亮和关系标签。
- `components/drawer-layout.ts` 与现有 Sheet：复用详情抽屉布局和焦点管理，不重新实现通用弹层。
- `features/models/components/model-connections.tsx`：已有渠道/分组关联展示，但缺少渠道 ID、优先级、权重、映射链与分组筛选，不能直接作为本页主体；沿用其关联语义及现成组件。
- `features/dashboard/components/flow/flow-charts.tsx` 与 `lib/flow.ts`：适合实际用量桑基图，不适合无用量配置边或优先级语义；第二交付评估复用图表配置和选择交互。

首版采用已在仓库依赖与本地封装中存在的 React Flow（`@xyflow/react`），用项目组件组成图节点、工具栏和抽屉；VChart 保留用于后续用量/趋势图。无需并行引入 ECharts 或 D3。当前 `@xyflow/react` 位于 devDependencies，实现时核对构建安装方式，作为正式页面运行依赖移入 dependencies 并保持锁定版本，避免生产构建缺失；本轮未安装或修改依赖。

现有封装缺少本功能的分组拓扑数据投影、树/网络布局、展开状态与关系级诊断，因此需要 feature 层业务图构建器；通用画布、节点卡片、控件、表格和抽屉优先复用或兼容扩展。布局函数与数据投影保持独立于 React 渲染，可直接测试。

遵循现有 i18n、数字格式、暗色、移动端与无障碍规范。模型/渠道长名称可查看完整文本；状态不只靠颜色；加载、无模型、无启用渠道、映射异常和刷新失败都需要独立表达。

## 8. 上游兼容与验证

- 不修改 channels、abilities、models、日志或 quota_data 的表结构；不改已有接口响应。
- 不修改普通选择、重试、模型映射、计费或额度扣减行为；发现既有差异时单独报告，不夹带修复。
- 将上游字段和映射语义适配集中在新模块。升级时核对 `model/channel_cache.go`、`model/ability.go`、`service/channel_select.go`、`relay/helper/model_mapped.go` 和统计数据口径。
- 可通过移除页面入口和新路由回退，无数据迁移或清理要求。
- 新查询仍影响数据库行为；实现后按项目要求在真实 SQLite、MySQL、PostgreSQL 上验证。若后续读取独立日志库，也需覆盖所支持的日志库路径，不能只以编译成功宣称兼容。

验收覆盖：

1. 空分组、未登记倍率但被渠道引用的分组、多分组渠道、相同模型跨组配置隔离。
2. 模型未入库或被模型库隐藏仍能显示配置；禁用渠道与无流量模型不消失。
3. 同优先级并列、不同优先级分层、零权重、只有一个渠道，不显示虚假的确定调用顺序。
4. 无映射、多步映射、自身映射、循环、非法映射、长模型名及包含 `/` 的模型名。
5. channels/abilities 不一致只展示诊断，不写数据；刷新不重建运行时缓存。
6. 无权限访问不泄露渠道配置；响应字段不含密钥或认证信息。
7. 分组/模型切换、URL 恢复、分页筛选、空/错/加载状态、键盘操作和移动端布局。
8. 后续指标覆盖无数据、聚合延迟、历史删除配置，并明确已记录消费与全部请求的区别。
9. 树模式同渠道可重复但 ID 不冲突；网络模式渠道合并，模型关系上的优先级、权重与映射不串线。
10. 搜索可发现未加载模型，局部详情失败可重试；分页、节点预算和加载更多不会静默伪装成全组完整拓扑。
11. 缩放/平移、折叠、模式切换、高亮、抽屉开关与配置刷新维持约定视角；删除键、连线操作及控件不能修改配置。

当前仅编写和核对设计，没有运行产品代码测试，也没有声明数据库验证通过。
